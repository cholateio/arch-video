# Development

Everything you need to pick this project back up after months away.

## Restart in 30 seconds

```bash
cd skill
npm install
npx hyperframes browser ensure   # 第一次才需要：取得渲染用的無頭 Chrome
npm test                         # 單元測試，不連網
npm run demo                     # 產出 out/demo/demo.mp4（配音需要連網）
```

## Commands

以下都在 `skill/` 裡執行。

| Command | Purpose |
|---------|---------|
| `node scripts/arch-video.mjs doctor` | 體檢：Node、相依套件、ffmpeg、無頭 Chrome、配音連線。缺套件時也能跑 |
| `npm test` | 單元測試：時間軸、觸發點、場景合成、機密掃描、配音的快取與熔斷、體檢、素材檢查。不連網、不渲染，約五秒跑完 |
| `npm run demo` | 整條流程跑一次：配音、合成、lint、預覽圖、渲染、成品檢查。任一步失敗會以非零結束 |
| `npm run stills` | 只產出預覽圖，不渲染也不配音（配過音的句子用快取）；改版面時用這個比較快 |
| `node scripts/arch-video.mjs material <專案>` | 確認素材庫裡這個專案的素材可以用來做影片（存在、審核過、沒過期），印出不能講的條目與工作資料夾 |
| `node scripts/arch-video.mjs build <分鏡檔>` | 產出任一份分鏡的影片。分鏡寫了 `meta.material` 時先確認素材、核對每個場景的 `basis` |
| `... --stills-only --voice` | 預覽時也配音，時間才準（調整版面與動畫時用）。不加 `--voice` 的預覽不連配音服務，沒配過音的句子用字數估算時間 |
| `... --theme blueprint` | 臨時換主題，輸出到 `out/<name>-blueprint/` |
| `... --out <資料夾>` | 指定輸出位置，預設是目前資料夾底下的 `out/` |

素材 skill 的指令在 `skill-material/` 裡執行，不需要 `npm install`。

| Command | Purpose |
|---------|---------|
| `npm test` | 單元測試：解析、格式檢查、座標、版本比對。會在暫存資料夾建立小的 git repo，約二十五秒 |
| `node scripts/arch-material.mjs init` | 建立素材庫（預設 `~/arch-material/`），權限只給自己 |
| `node scripts/arch-material.mjs check <素材檔>` | 檢查格式、座標指不指得到、背景知識、機密 |
| `node scripts/arch-material.mjs status <素材檔>` | 來源和素材記錄的版本比起來改了什麼、哪些條目要重新查證 |
| `node scripts/arch-material.mjs stamp <素材檔>` | 印出現在的 commit 與不在版控來源的指紋，貼進素材的版本表 |

## Environment variables

不需要 `.env`，也沒有金鑰。

| Variable | Purpose |
|----------|---------|
| `HTTPS_PROXY` | 選填。配音連線要經過代理伺服器時設定 |
| `HYPERFRAMES_BROWSER_PATH` | 選填。指定已安裝的 Chrome 執行檔，HyperFrames 就不會自己下載 |
| `ARCH_MATERIAL_FONT_DIRS` | 選填。`arch-material shot` 截圖時另外加給 Chrome 的字型資料夾（多個用路徑分隔字元隔開）。Linux 常缺彩色表情符號的字型，截出來會變成方塊；WSL 會自動加上 Windows 的字型 |

## Easy to forget

- **`hyperframes browser path` 會順便下載 Chrome**，不是唯讀指令。體檢因此只看環境變數與快取資料夾，不呼叫它。
- **進入點用動態載入**：`scripts/arch-video.mjs` 依指令才載入模組，沒裝相依套件時 `doctor` 才跑得起來。
  `lib/doctor.mjs` 不可以在檔案開頭載入 `node_modules` 裡的東西。
- **數字從 0 數上去要用 `fromTo`**：`from({ innerText: 0 })` 會讓數字停在 0（見 `scenes/stat.mjs`）。
- **換章節的 `wipe` 會自動輪流三種樣式**（橫條、圓形、直條），依出現的次序決定，不是寫在分鏡裡。
- **`<audio>` 一定要有 `id`**，否則 HyperFrames 渲染出來沒有聲音，而且不會報錯（lint 才會抓到）。
- **觸發詞用字元位置對時間。** 配音服務的斷詞會把詞切開（「十二個」變成「十」「二個」），
  所以 `timeline.mjs` 把各段文字接起來找起始字元，不直接比對詞。
- **有 `say` 的句子，觸發詞要從 `say` 裡挑。** 時間戳來自實際唸出來的文字。
- **機密掃描排在配音之前。** 旁白文字會送到外部的配音服務，所以 `build.mjs` 先跑 `secrets.mjs` 的 `scanBoard()`，有發現就停。
  回報時只印遮蔽後的片段。`meta.allow` 只接受和找到的內容完全相同、至少六個字的字串。測試裡的假金鑰要在執行時拼出來，不要寫成完整的字面值，否則 commit 會被 kit 的機密檢查擋下。
- **觸發點比旁白早 0.8 秒，而且對齊子句的開頭，不是觸發詞本身。** `timeline.mjs` 的 `CUE_LEAD` 控制提前量；
  子句靠配音回傳的詞尾標點判斷。同一個子句的後續觸發詞最多再晚 0.3 秒，所以每個觸發點至少比子句早 0.5 秒：
  元件內部再加的延遲（例如圖示、標籤晚 0.3 秒）不可以超過 0.5 秒。打字效果要在旁白講到之前打完（用 `ctx.deadline()`）。
- **可以「畫出來」的線不能直接帶箭頭。** 箭頭是另一個元素，線畫完才顯示，否則箭頭會先出現在終點（見 `scenes/map.mjs`）。
- **GSAP 要動的元素不要在 CSS 寫 `scale(0)` 這類變形。** 初始狀態用 `ctx.init()` 或 `fromTo` 設定。
- **字型與 GSAP 是從 `node_modules` 複製進輸出專案的**，渲染時不連網。
- **「講原因的句子太少」的門檻是量出來的。** `build.mjs` 的 `MIN_REASON_SHARE` 是 15%：改版前的三支影片是 2% 到 6%，
  照新規則寫的第一支是 21%。樣本只有四支，之後有新的數據再調。它只數連接詞，擋不住硬塞的「因為」，原因對不對仍然要靠審核。
- **`skill/examples/arch-blueprint/` 是改版前的分鏡**，現在建置會出現「講原因的句子太少」的警告。它留著當格式與版面的範例，不是腳本寫法的範例。
- **配音快取在 `skill/.cache/tts/`**，鍵是「聲音＋語速＋文字」。換聲音或改一個字都會重新合成那一句。
- **配音全部連不上時不會中斷**：成品是純字幕版，並列出警告。只失敗一部分時會停下來、不渲染（重跑會用快取補齊）。
- **配音服務會限流。** 短時間配太多句（實測約一小時內 290 句）會開始回 429；`tts.mjs` 遇到會等 15、30、60 秒再試。
  連續兩句失敗後，這次執行剩下的句子直接略過，不再逐句等逾時（`lib/tts.mjs` 的熔斷）。
- **預覽總表逐一列出輸入檔，不用 glob**：Windows 的 ffmpeg 不支援 `-pattern_type glob`。
- **WSL 沒有硬體 GPU**，HyperFrames 會印一段軟體渲染的提示，可以忽略。
- **靜態預覽圖取的是每個場景「最後一句剛講完」的那一刻**，所有元素都已出現、下一個轉場還沒開始。
- **藍圖地圖的顏色是字串替換來的**：arch-blueprint 的圖固定用 `#faf8f4` 與 `#1a1a1a`，
  `scenes/map.mjs` 把這兩個值換成主題的顏色。arch-blueprint 若改了配色，這裡要跟著改。

- **素材的座標是對著「素材記錄的 commit」檢查的**，不是對著工作區。來源多了 commit 之後 `check` 仍然會過，要看有沒有過期是 `status` 的事。
- **commit 釘不住的來源用內容指紋比對**，兩種：不在版控裡的檔案（例如被 kit 排除的 `docs/LESSONS.md`、普通資料夾裡的東西），
  以及被主張引用、又有還沒 commit 的修改的檔案或資料夾。指紋相同代表「整理時看過、之後沒再變」，不再算過期。
  哪些來源要記指紋只定義在 `skill-material/lib/local.mjs` 的 `expectedPrints()`，`check`、`status`、`stamp` 都用它；改規則只改這裡。
- **`status` 的「過期」只看素材引用到的東西。** 來源裡沒被引用的未 commit 變動列為提醒，不算過期；
  否則使用者只要有開發到一半的修改，素材就永遠顯示過期。一手文件地圖裡的座標也不算引用（它只記「讀過」）。
- **符號連結一律不跟過去。** 座標指到連結會報錯；資料夾的指紋把連結算成「指向哪裡」，不讀它後面的內容。
- **`check` 只驗證座標指得到東西，不驗證主張對不對。** 第一次實跑時 `check` 全過，另一個模型回原始碼查出 13 處內容問題
  （主旨被自己的一條事實推翻、拿舊註解當現在的原因、說過頭）。所以流程裡有一步強制交給另一個查證者（`references/verify-checklist.md`）。
- **素材 skill 靠相對位置找到機密掃描**：`skill-material/lib/shared.mjs` 依序找 `../skill` 與 `../arch-video`。
  兩個 skill 沒有放在同一層時 `check` 會直接報錯，不會跳過掃描。
- **「建議整份重新整理」數的是被引用的位置，不是變動的檔案。** 一個資料夾座標底下改了六個檔案只算一個位置；
  原本照檔案數，真實專案上一個 commit 就被判成要整份重來（16 個位置裡其實只有 3 個變了）。
- **`stamp` 記下的是現在 checkout 的版本，不管你查證到哪裡。** 來源在整理期間又多了 commit 時，貼上新的版本表等於替沒看過的內容蓋章
  （實際發生過：使用者同時在另一個視窗改來源 repo）。`stamp` 會印出「版本會從 … 換成 …」，更新流程也要求先跑 `status`。
- **出處的文件被刪掉時，座標只能指到最後還有它的 commit**（`代號@commit`），`check` 只確認那個 commit 存在，不會去那個版本裡找檔案與小節。
  素材的缺口要寫明原文得從 git 歷史取。
- **影片 skill 的素材檢查不重寫一套**：`skill/lib/material.mjs` 的 `gate()` 載入素材 skill 的 `check` 與 `status`，
  擋下不存在、沒通過檢查、沒審核、過期這四種情況；`build`（含預覽）與 `material` 指令都走它。
  來源裡沒被素材引用的未 commit 變動只印提醒，不擋。
- **`basis` 只核對編號**：在不在素材裡、是不是〔不明〕或〔查不到〕。旁白是不是真的只講了那幾條，程式看不出來，靠審核點二與審核清單。
- **`meta.material: false` 只給不講真實專案的分鏡**（`examples/demo`）。`examples/arch-blueprint` 是改用素材之前的分鏡，
  沒有 `meta.material`，建置會多一個警告。
- **工作資料夾預設在素材庫裡**（`<素材庫>/video/<專案>/`），所以編排、分鏡、成品和素材一樣只有 owner 讀得到，也不會出現在專案裡。
